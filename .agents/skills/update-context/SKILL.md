# Update Context

## Purpose

Этот skill нужен для поддержания AI Workspace в актуальном состоянии.

Анализируй новую информацию пользователя и при необходимости обновляй:

- `context/profile.md`
- `context/business.md`
- `context/goals.md`
- `context/preferences.md`

Не проводи полный onboarding, если это не требуется. Все пути указаны относительно корня репозитория.

## Workflow

### Step 1 — Read current context

Проверь и прочитай существующие персональные файлы:

- `context/profile.md`
- `context/business.md`
- `context/goals.md`
- `context/preferences.md`

Если файла нет, не считай это ошибкой. Используй соответствующий `*.example.md` как структурный шаблон, если нужно создать новый файл.

### Step 2 — Identify new persistent information

Определи, какая информация из текущего запроса пользователя действительно полезна для будущих задач.

Сохраняй только информацию, которая:

- вероятно останется актуальной какое-то время;
- может изменить будущие ответы AI;
- относится к профессиональному профилю, работе, бизнесу, целям или предпочтениям.

Не сохраняй:

- временные детали;
- случайные факты;
- одноразовые задачи;
- passwords;
- API keys;
- tokens;
- banking credentials;
- другие секреты.

Не записывай догадки как факты.

### Step 3 — Compare with existing context

Сравни новую информацию с уже сохранённой. Определи:

- new information — новая информация;
- updated information — обновление ранее сохранённой информации;
- duplicate information — информация, которая уже сохранена;
- conflicting information — информация, противоречащая существующей.

Не дублируй уже существующую информацию, в том числе между файлами.

Если новая информация противоречит существующей, не перезаписывай старую молча. Покажи пользователю конфликт и попроси подтвердить, какая версия актуальна. Дождись ответа перед изменением конфликтующих данных.

### Step 4 — Propose changes

Перед изменением файлов покажи краткое summary:

- какой файл будет изменён или создан;
- что будет добавлено;
- что будет обновлено;
- что будет удалено, если удаление действительно необходимо.

Если изменения значимые или конфликтуют с существующим контекстом, дождись подтверждения пользователя. Для небольших изменений без конфликтов используй явное поручение пользователя сохранить или обновить эти данные как подтверждение; если такого поручения нет, запроси подтверждение перед записью.

Если полезных изменений нет, сообщи об этом и не изменяй файлы.

### Step 5 — Update files

После подтверждения обнови только необходимые файлы из списка в Purpose. Создавай отсутствующий файл только тогда, когда для него есть подтверждённая постоянная информация.

Сохраняй структуру понятной и компактной. Не переписывай весь файл без необходимости. Сохраняй информацию, не затронутую согласованными изменениями.

Не создавай дубликаты. Не изменяй `*.example.md`.

### Step 6 — Finish

После обновления покажи:

- какие файлы изменены или созданы;
- какие данные добавлены или обновлены, а также удалены, если применимо;
- были ли обнаружены конфликты и как они были разрешены либо какие остались нерешёнными.

Не изменяй:

- `AGENTS.md`;
- `decisions/`;
- `references/`;
- другие skills;
- любые файлы вне перечисленных персональных файлов `context/`.

Не делай `git commit` или `git push`.
